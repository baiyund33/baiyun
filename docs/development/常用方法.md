#### 1.`strings.TrimSpace()` 用于去掉字符串**开头和结尾的空白字符**，包括空格、换行和制表符：
```go
strings.TrimSpace("  baiyun  ") // 得到 "baiyun"
strings.TrimSpace("   ")       // 得到 ""
```

#### 2.错误
`codes.InvalidArgument` 是 gRPC 的错误状态码，表示：**客户端传入的参数不合法**。

例如：

```
return nil, status.Error(codes.InvalidArgument, "id、name、phone 必须填写")
```

- `codes.InvalidArgument`：错误类别，编号为 **3**。
- 后面的字符串：具体错误说明。

客户端收到后，就知道需要修正请求参数。

#### 3.判断字符串是否包含
`strings` 包中，相关方法主要有这些：

| 方法                      | 作用           | 示例                                              |
| ----------------------- | ------------ | ----------------------------------------------- |
| `Contains(s, substr)`   | 是否包含完整子串     | `Contains("hello", "ell")` → `true`             |
| `ContainsAny(s, chars)` | 是否包含集合中的任意字符 | `ContainsAny("hello", "ae")` → `true`           |
| `HasPrefix(s, prefix)`  | 是否以指定内容开头    | `HasPrefix("hello", "he")` → `true`             |
| `HasSuffix(s, suffix)`  | 是否以指定内容结尾    | `HasSuffix("user.go", ".go")` → `true`          |

#### 5.m.conn.ExecCtx(ctx, query, message, id)
```sql
update friend_request set `message` = ?, `status` = 0 where `id` = ? and `status` = 2
```
#####  调用的方法：`m.conn.ExecCtx`

- **`m.conn`**：代表数据库连接（通常是 `go-zero` 框架中的 `sqlx.SqlConn`）。
    
- **`Exec`**：意思是“执行”（Execute）。在 Go 数据库操作中，`Exec` 专门用来执行不需要返回数据集合（Rows）的 SQL 语句，比如 `INSERT`（插入）、`UPDATE`（更新）和 `DELETE`（删除）。
    
- **`Ctx`**：代表它接收一个 `context.Context` 参数，这在现代 Go 开发中非常重要，用于超时控制、链路追踪或取消请求。
    

##### 传递的参数：`(ctx, query, message, id)`

- **`ctx`**：上下文控制变量，传递给底层数据库驱动。
    
- **`query`**：就是你上一问中提到的那串包含 `?`（占位符）的 SQL 字符串。
    
- **`message, id`**：这两个是**实际的参数值**。它们会按照顺序，**依次替换**掉 `query` 字符串里的两个 `?`。
    
    - 第一个 `?` 被替换为 `message` 的值（即最新的好友申请附言）。
        
    - 第二个 `?` 被替换为 `id` 的值（即好友申请的记录 ID）。
        
    - **重点**：这种传参方式叫做“预编译参数绑定”，它由底层数据库驱动安全地拼接，能**绝对防止 SQL 注入攻击**，你不需要手动去转义字符串里的引号。
        

##### 返回的结果：`result, err :=`

- **`err`**：如果执行过程中发生网络断开、SQL 语法错误等问题，这里会返回一个错误。代码下一行紧接着做了 `if err != nil` 的错误处理。
    
- **`result`**：如果执行成功（没有报错），会返回一个 `sql.Result` 对象。它虽然不包含具体的表数据，但包含**操作的元数据**。你代码后面的 `result.RowsAffected()` 就是用它来查看“这条 SQL 到底成功修改了多少行数据”。（如果查不到符合 `id=? 且 status=2` 的数据，影响行数就是 0）。

#### 7.strconv.ParseInt
JWT 中的 `userId` 是字符串，而 RPC 参数需要 `int64`，因此使用 `ParseInt`：

```go
fromID, err := strconv.ParseInt(userId, 10, 64)
```

例如将 `"16"` 转为数字 `16`；`10` 表示十进制，`64` 表示结果使用 64 位整数。


#### 8.TransactCtx
是 **go-zero 的 `sqlx` 提供的方法**，不是你编写的。

```
l.svcCtx.MysqlConn.TransactCtx(...)
```

各部分含义：

|部分|含义|
|---|---|
|`l.svcCtx`|当前服务的依赖容器|
|`MysqlConn`|你初始化的数据库连接|
|`TransactCtx`|框架提供的开启、提交和回滚事务的方法|

使用方式：

```go
err := l.svcCtx.MysqlConn.TransactCtx(
	l.ctx,
	func(ctx context.Context, session sqlx.Session) error {
		// 使用 session 执行属于本次事务的 SQL。

		return nil
	},
)
```

它会按这个顺序工作：

```
开启事务
   ↓
调用你传入的函数，并提供事务 session
   ↓
函数返回 nil → 提交事务
函数返回错误 → 回滚事务
```

你负责写**事务里面要执行的操作**，框架负责管理事务。

类似 Java 的 `@Transactional`，但 Go 这里通过函数明确指定事务范围，而且 SQL 必须使用传入的 `session` 才能加入事务。
