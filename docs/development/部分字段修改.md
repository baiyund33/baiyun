可以，这是**部分字段更新**：ID 必须有效，其他字段只有非空时才修改。

建议明确规则：

|输入|行为|
|---|---|
|没传 `name` 或 `phone`|保持原值|
|传入 `""` 或只有空白|保持原值|
|传入非空值|校验后修改|
|两个字段都为空|确认用户存在后返回成功，不执行更新|

当前有两处阻止这个行为：

1. **API 字段是必填的**，省略字段可能在请求解析阶段被拒绝。应改为：
    
    ```
    Name  string `json:"name,optional"`
    Phone string `json:"phone,optional"`
    ```
    
2. **RPC 要求两个字段都非空**：
    
    ```
    if in.GetId() <= 0 || name == "" || phone == "" {
    ```
    
    应只要求 `id > 0`，对非空字段分别处理。
    

还有一个细节：生成的 `UserModel.Update` 会更新 `name`、`phone`、`password_hash` 全部字段。虽然可以先查询旧值，再只修改非空属性，但并发请求可能覆盖其他字段的新值。

**推荐增加自定义 model 更新方法，只把本次非空字段写入 SQL，不修改生成文件。** 手机号唯一索引、重复错误处理、JWT 和本人权限检查继续保留。


修改三处，**不需要修改 proto，也不要修改生成的 `usermodel_gen.go`**。

**2. model 增加部分更新方法**

在 [usermodel.go](E:/code/baiyun/apps/user/rpc/models/usermodel.go) 的 `UserModel` 接口内增加：

该文件导入 `"strings"`，然后增加方法：

```
func (m *customUserModel) UpdateFields(
    ctx context.Context, id int64, name, phone string,
) error {
    var fields []string
    var args []any

    if name != "" {
        fields = append(fields, "`name` = ?")
        args = append(args, name)
    }
    if phone != "" {
        fields = append(fields, "`phone` = ?")
        args = append(args, phone)
    }

    // 没有需要更新的字段，不执行 SQL。
    if len(fields) == 0 {
        return nil
    }

    args = append(args, id)
    query := fmt.Sprintf(
        "update %s set %s where `id` = ?",
        m.table, strings.Join(fields, ", "),
    )
    _, err := m.conn.ExecCtx(ctx, query, args...)
    return err
}
```

只修改名字时，SQL 就只有：

```
UPDATE user SET name = ? WHERE id = ?
```

手机号和密码哈希不会被写入本次更新。
