
```go
// 收到心跳回应，延长连接的等待时间。
conn.SetPongHandler(func(string) error {
	return conn.SetReadDeadline(time.Now().Add(60 * time.Second))
})

// 通知后台心跳任务：连接已经结束。
done := make(chan struct{})
defer close(done)

// 后台定期发送心跳，不阻塞下面的消息读取。
go func() {
	ticker := time.NewTicker(20 * time.Second)
	defer ticker.Stop()

	for {
		select {
		case <-ticker.C:
			err := conn.WriteControl(
				websocket.PingMessage,
				nil,
				time.Now().Add(10*time.Second),
			)
			if err != nil {
				conn.Close()
				return
			}

		case <-done:
			return
		}
	}
}()
```
这段代码实现了**定期检查连接是否还活着，并在连接结束后停止心跳任务**。

服务端每隔 20 秒发送一次 `Ping`，客户端回复 `Pong`；服务端收到回应，就把读取超时延长到当前时间之后的 60 秒。

**1. 收到 Pong，延长读取期限**

```go
conn.SetPongHandler(func(string) error {
    return conn.SetReadDeadline(
        time.Now().Add(60 * time.Second),
    )
})
```

`SetPongHandler` 注册一个回调函数：收到 WebSocket 的 `Pong` 控制帧时执行它。

```go
func(string) error
```

表示这个函数接收一个字符串参数，返回一个错误。字符串是 Pong 携带的内容，这里不需要使用，所以省略了参数名。

```go
time.Now().Add(60 * time.Second)
```

计算“现在往后 60 秒”的时间点。`SetReadDeadline` 把它设置为读取截止时间。

例如：

```text
12:00:20 收到 Pong → 截止时间更新为 12:01:20
12:00:40 收到 Pong → 截止时间更新为 12:01:40
```

如果之后没有收到回应或业务消息，读操作最终会超时，项目中的 `ReadMessage()` 返回错误，handler 随之退出。

注意：**Pong 回调需要读取连接才能触发**。你后面的 `ReadMessage()` 循环会在读取过程中处理 Pong；浏览器通常会自动回复 Pong，不需要 JavaScript 手动发送。

**2. 创建退出通知**

```go
done := make(chan struct{})
defer close(done)
```

`channel`（通道）用于在不同并发任务之间传递数据或通知。

这里的 `chan struct{}` 不传业务数据，只用来通知：“这个连接已经结束”。

```go
defer close(done)
```

表示当前 handler 退出时关闭通道。关闭后，后台任务中的：

```go
case <-done:
```

就能立即被触发，使心跳任务退出。这里不需要执行 `done <- ...` 发送数据。

**3. 启动后台心跳任务**

```go
go func() {
    // ...
}()
```

`go` 启动一个 goroutine，也就是 Go 的并发执行任务。结尾的 `()` 表示调用这个匿名函数。

于是两项工作可以同时进行：

```
handler：不断读取消息、回显消息
心跳 goroutine：每隔 20 秒发送 Ping
```

如果没有 `go`，代码会一直停留在这个心跳循环里，无法执行下面的消息读取。

**4. 每隔 20 秒收到一次定时通知**

```go
ticker := time.NewTicker(20 * time.Second)
defer ticker.Stop()
```

`ticker` 是定时器，它每隔 20 秒向 `ticker.C` 通道发出通知，首次通知也在约 20 秒后。

心跳 goroutine 退出时，`ticker.Stop()` 停止定时器，释放相关资源。

**5. 等待定时通知或退出通知**

```go
for {
    select {
    case <-ticker.C:
        // 发送 Ping
    case <-done:
        return
    }
}
```

`for` 让任务持续运行，`select` 同时等待两个通道：

|收到的事件|执行的操作|
|---|---|
|`ticker.C` 定时通知|发送一次 Ping|
|`done` 被关闭|结束心跳 goroutine|

没有事件时，`select` 会等待，不会不停空转。

**6. 发送 Ping，并处理失败**

```go
err := conn.WriteControl(
    websocket.PingMessage,
    nil,
    time.Now().Add(10*time.Second),
)
```

三个参数分别是：

- `websocket.PingMessage`：发送 Ping 控制帧。
- `nil`：不携带额外内容。
- 最后一个时间：本次发送的截止时间，最多等待约 10 秒。

这里的 **10 秒限制发送操作**，不是等待 Pong 的时间；Pong 是否及时返回由读取期限控制。

```go
if err != nil {
    conn.Close()
    return
}
```

如果 Ping 发送失败，就关闭连接，并结束心跳任务。关闭连接也会让另一边正在等待的 `ReadMessage()` 返回错误，从而退出 handler。

你这里使用 `WriteControl` 很关键：Gorilla WebSocket 允许它与其他连接操作并发调用。因此，后台发送 Ping 可以与 handler 中的 `WriteMessage` 回显同时进行；普通 `WriteMessage` 则不能由多个 goroutine 同时调用。

完整过程是：

```
每隔 20 秒发送 Ping
    ↓
客户端回复 Pong
    ↓
读取循环触发 Pong 回调
    ↓
读取期限延长到当前时间之后 60 秒

连接出错或读取超时
    ↓
handler 退出，关闭 done 和 conn
    ↓
心跳任务收到退出通知，停止 ticker 并退出
```
